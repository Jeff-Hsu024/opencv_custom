# Workflow Lifecycle Management v1
Application layer; SQLite registry in recorder store. Immutable content-addressed bundles remain authoritative. Explicit named family (slug), same device/profile across versions, monotonically numbered versions; explicit parent version on registration. Require an already completed Runtime run, verified step receipts and fresh-frame guards/targets rechecked offline; version registration does not activate. Subsequent versions preserve family goal (explicit review note) and actual initial/final parent visual guards; no inferred semantic equivalence. Unregistered workflows remain available for deliberate qualification/legacy use. One active version per family, no automatic promotion. Activation/disable/rollback use compare-and-swap expected generation under workspace lock, append audit log in same transaction. Rollback only previously activated version; disabled means no active version, not deletion. Managed inactive versions cannot run via direct Runtime binding; same run ID returns existing receipt without action. No restriction on independent observation or offline inspection.
Recovery links exact parent version to child qualification from Phase 5; revalidate qualification and its source, child and parent hashes before enabling/selecting. Link is explicitly enabled, separate from primary version family. Child cannot also be a primary version; parent must be active for child execution. Disable link prevents child runtime even with old binding. Candidate selection from actual failed run with not_attempted and PRECONDITION_FAILED only; verifies parent is active, exact profile, observes fresh full frame, requires parent classification unknown or nonambiguous and child initial guard + unique target. Match recorded anchor parent classification. Zero/multiple matching routes => no selection; corrupted enabled evidence => fail closed. Selection returns recommendation, fresh frame and lineage; never clicks, qualifies, resumes or retries. Explicit qualify/run required. Existing external controllers not locked. Max 20 registered routes per parent, bounded pages. Audit is append-only application contract, not security boundary against DB admins.
CLI/MCP register/activate/disable/rollback/inspect/list/history/link/route-status/select. Version/route mutation requires expected generation and reason. First registration generation 0 -> 1. Explicit version registration + activation separate. No GUI, scheduling, automatic LLM invocation or workflow editing.
