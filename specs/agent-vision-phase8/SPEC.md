## 3. AO-01 — Schemas and errors
Publish exact annotation/checkpoint field set (purpose, state, expected_postcondition, observation, verification, failure_reason, insight, next_step, completed_steps, unresolved_issues), enum PASS/FAIL/UNKNOWN, nonempty object, additionalProperties false, explicit allowed value shapes consistent with existing stored data/callers; inspect actual fixtures before narrowing. Existing default verification and annotation size limit 8000 serialized characters preserved. Reject unknown fields before mutation; error reports offending field names and allowed keys, not secret values. RecorderError maps to stable recorder error codes, distinguish invalid arguments, missing IDs, inactive session and scope. Do not map unknown implementation failures to user error. MCP isError / CLI exit semantics consistent; structured error code/details/retryability. Contract tests for every field, legacy input, malformed/extra fields, no mutation on validation rejection, no secret leakage.

## 4. AO-02 — High-level recorded transition
Add application service composing existing primitives and Recorder. New MCP vision_transition and CLI vision transition. Required explicit device, session_id (active), transition_id (trans_<32 lowercase hex>), expected target asset, threshold or documented default, postcondition {mode:changed|image, timeout, optional region/target}, max_ref_age_seconds and bounded return_image option; validate all inputs and target asset before action. No implicit session or desktop fallback. Scope V1 to full-frame reference-based click, unique target, bounded wait. Agent must know intended action and expected postcondition before invoking; optional known pre-state marker guard (if provided must be unique) is not semantic inference.
One cross-process workspace lock for entire sequence. Refactor Recorder to private locked operation implementation; public execute still acquires lock; no recursive lock. Persist request + progress before first primitive, unique transition ID and payload identity; same ID returns receipt, never replays; conflicting payload rejected. Interrupted request reconciles existing event IDs/status and preserves unknown effect; no automatic continuation. Child events exactly snapshot, find, click, wait, snapshot; session-bound normal receipts, sequence/order, protected source evidence, scoped ref and actual wait output, same existing Builder contract. No synthetic successes, no hidden click retries; failed primitive stops normal sequence (optional read-only recovery observation explicitly recorded, never action). Persist click pending before actual click. Target none/multiple or stale => stop before click; wait failure/timeout => action may be executed_unverified, not success; final screenshot failure => needs_agent. If last capture can safely be taken after failed wait, label it as diagnostic and do not present as verified path. Return transition_id, status (observed/needs_agent/interrupted), action_outcome (not_attempted/unknown/executed_unverified), event IDs (pre/find/action/wait/post), latest frame ID, match count/score, observed wait result, reason. Never claim semantic PASS automatically. Agent examines post-image and separately annotates actual post snapshot; optional return_image uses standard MCP ImageContent, no base64 in text; CLI returns artifact metadata. For known guard-based task prefer existing Runtime/Orchestrator over transition. No rollback guarantee.

## 5. AO-03 — Bounded responses
Define response_mode summary|detail|full and contract table for selected high-volume workflow build/validate/inspect, runtime/task inspect, recovery propose/inspect and recorder queries. Additive modes; legacy default full unchanged. New Skill requests summary explicitly. Summary includes identity, status, counts, reason, evidence pointers and pagination; never omits uncertainty/failure or needed IDs. Detail bounded selection/pagination by step/event ID or cursor; full preserves existing payload. All modes derive from same stored evidence, same hashes and domain outcome; no change to build identity or persisted data. No base64 in metadata. Measure serialized UTF-8 bytes using same four-step recorded path; target >=70% reduction for Builder summary versus full, report actual bytes (not tokens). Bound summary to 8 KiB for ordinary successful four-step build, independent of provenance volume; failure details bounded but actionable. Full mode remains opt-in by new Skill, available for audit. No claim of actual token savings without telemetry.
