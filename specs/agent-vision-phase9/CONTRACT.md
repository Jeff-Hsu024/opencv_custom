# Phase 9 contract v1
Status: REVIEW_RESOLVED_DESIGN. Normative for C00 and all successor tickets. No code implemented.
Scope: one host, one ADB server, one canonical shared Store, cooperating upgraded CLI/MCP processes. No external controller or cross-store exclusion, physical-device attestation, unattended re-exploration, new workflow action types, or automatic portable recovery.
This contract resolves conflicting earlier SPEC examples. The portable run/task prefixes are prun_/ptask_, not legacy run_/task_. Batch prefix is batch_. C00 turns the specified request schema catalog and acceptance examples into executable contract fixtures; it must not reopen product decisions. Any change requires explicit SPEC/contract revision and manifest refresh before affected implementation.

## K01. API and transport
Each tool is vision_<operation> below; CLI is "vision phase9 <operation-with-hyphens> --request <JSON-file>" (UTF-8 JSON object; existing --store-dir applies). Same service and validation on both. Existing 61 MCP tools/CLI shapes and names unchanged. New operations are additive. CLI group is deliberately uniform, no separate flag parser per operation. Request schema catalog CONTRACT_SCHEMAS.json is normative: strict object, unknown fields rejected, booleans not integers, defaults materialized before request hashing. Limit 1..50, default 20; after nonnegative durable integer cursor default 0; ordered row sequence, next_cursor null at end. No implicit selection; all device-effect paths require exact serial. New strict discovery returns online ADB serials, not desktop, and fails on malformed output/command failure; old vision_devices keeps legacy shape and desktop. Narrow Core parser fix for exact state token allowed; no wider Core refactor. JSON serial pattern rejects adb and desktop aliases; validate online at execution admission, do not launch/connect.

Success: {"ok":true,"result":{...}}. Rejection before durable effect request admission: {"ok":false,"error":{"code":"...","message":"...","details":{},"retryable":false}}. Exact required fields; details object may be empty. Once a durable effect request exists, status is returned as success envelope even when needs_agent/interrupted/busy/rejected, with reason object or null and actual action_outcome. No transport success implies semantic success. CLI exit 0 for successful query, completed effect or in_progress inspection; 2 invalid request shape; 3 other pre-admission rejection or terminal non-completed effect; 4 pre-admission capture/transport timeout; inspect/list always 0 on successful retrieval. MCP isError=true only for ok:false; an accepted receipt is ordinary text result, including failed task outcome. Preserve existing legacy mapping separately. Native ImageContent only where request schema has return_image; when true and valid actual observed frame exists, return metadata TextContent followed by image/png bytes of that frame. No image inside JSON. False returns metadata only, no frame fabricated. Batch never fans out images. Error details never include raw typed text, image base64 or secrets.

Stable rejection codes: INVALID_ARGUMENT, INVALID_DEVICE, DEVICE_UNAVAILABLE, DISCOVERY_FAILED, NOT_FOUND, SCOPE_MISMATCH, DEVICE_BUSY, STALE_REF_EPOCH, REF_UNVERSIONED, FRAME_STALE, PROFILE_MISMATCH, GEOMETRY_MISMATCH, INITIAL_STATE_MISMATCH, TARGET_NOT_FOUND, TARGET_AMBIGUOUS, PRECONDITION_FAILED, EVIDENCE_CHANGED, PROOF_INVALID, QUALIFICATION_REQUIRED, QUALIFICATION_INACTIVE, STALE_GENERATION, FAMILY_INACTIVE, REQUEST_ID_CONFLICT, ID_RESERVED, STORE_ERROR, INTERNAL_ERROR, CAPTURE_TIMEOUT, INTERRUPTED, ACTION_UNCERTAIN. retryable=true only DEVICE_BUSY, DEVICE_UNAVAILABLE, DISCOVERY_FAILED, CAPTURE_TIMEOUT if no effect admission; retry after fresh observation as needed, never blindly reissue a new ID for uncertain effect. Failure receipt reason uses same code/message/details/retryable shape (retryable=false for admitted effect). Unexpected exceptions INTERNAL_ERROR, do not misclassify implementation failure as argument error.

The following result keys are required (null explicitly for unavailable optional evidence); additional diagnostics may appear only in details or nested legacy receipt. A list result always {items:[<entity summary>],next_cursor:integer|null}. All IDs are opaque. Stable timestamps Unix seconds; SHA-256 lowercase hex. Full detail inspection for runs/task/batch returns the same record with steps/children, summary list omits nested step bodies (counts and IDs retained).

Explicit revision use permits device-wide (null session) or exact same session only; no foreign session. - portable_publish/portable_inspect: {portable_id,source_workflow_id,source_run_id,source_device,source_seal,profile,geometry,step_count,template_sha256,created_at}; publish verifies original proof, deterministic ID excludes created_at; source seal includes original complete evidence.

- portable_trial/portable_trial_inspect: EffectReceipt, kind trial, prun_ ID; includes preflight_id, portable_id, context, steps, source_seal; trial complete is not enrollment. ## K03. Durable identity and owner contract (R07,R11,R14)
New additive SQLite coordinator DB/tables; no destructive migration. Canonical request JSON UTF-8, sorted keys, compact separators, disallow NaN; apply defaults, exact array order, preserve caller values (exclude response-only return_image from new effect identity; re-projection never reruns). Digests use SHA-256. Legacy identity normalization stays unchanged. ID prefixes: portable_, preflight_, qlf_, ar_ (64 hex); act_, strans_, prun_, ptask_, batch_ (32 hex); existing frm_/ref_/ses_/run_/task_/trans_ unchanged. Namespace ledger key full ID, kind, normalized request digest; legacy namespaces disjoint, migrate only live claims not rewrite historical JSON. Child IDs: ptask_ + first32 hex digest canonical {kind:"batch-child-task",batch_id,device}; prun_ + first32 digest {kind:"task-run",task_id,device}; reserve both at atomic parent admission. Collision is rejection, never silently adopt old ID. New admitted standalone task similarly reserves run. Exact duplicate lookup precedes freshness/generation checks, returns original receipt/in_progress with duplicate_request; different digest => REQUEST_ID_CONFLICT; a reserved child invoked independently => ID_RESERVED. Read-only inspect never dispatches.

Coordinator logical tables: request_claim(id PK,kind,request_hash,request_json,parent_id nullable,device nullable,owner_token nullable,state,receipt_json,created_at,updated_at); batch_admission(batch_id PK,phase,pinned_family,revision,portable_id,generation,ordered_children_json); device_epoch(device PK,epoch); qualification_slot(portable_id,device PK pair,generation,status,qualification_id,reason); qualification_record(id PK,immutable_json); qualification_mutation(op_hash PK,slot,generation,receipt_json); portable_family(id PK,generation,active_revision); portable_revision(family,revision PK pair,portable_id unique per family); evidence_revision(scope PK,generation); asset_revision(id PK,immutable_json,png_digest); scoped_asset_alias(device,session_key,name PK,revision_id); frame_epoch(frame_id PK,device,epoch); ref_epoch(ref_id PK,device,epoch). Actual storage layout may use equivalent additive tables with same constraints and semantics; authoritative new receipts in coordinator DB, immutable evidence on disk, atomic transaction for parent + claims + pinned IDs; JSON is compatibility/export projection, never authoritative for new IDs. Legacy existing JSON receipt formats retained. No old binary writers concurrently with upgraded Store. For legacy ID claims, check original receipt before claim, atomic ownership for new requests; receipt already terminal returned byte/shape-compatible.

Owner locks OS-backed across processes plus process-local mutual exclusion for threads; per-ID owner lock file keyed canonical store + full ID hash, per-device lock keyed store + exact serial hash (desktop gets its own legacy-only key); paths cannot escape Store. Locks never removed while usable (avoid inode replacement); released by process/thread finally or OS death. Global short metadata lock coordinates all file/index/SQLite writers and ID claims. Lock ordering: compatibility outer gate (during expand only) -> parent request owner -> independent child/request owner -> device owner -> metadata. Parent dispatcher may use metadata without device, child never reacquires parent owner. Nested run/transition under an admitted task uses its owner context, no recursive acquisition. No wait for owner/device while holding metadata. Never hold A device while waiting for B; independent device I/O outside metadata. Legacy caller bounded wait compatible with 120s; portable contention bounded <=2s. Busy before input yields durable busy child/task if admitted. All input entrypoints share device owner. Discovery and offline read-only queries do not control devices. If caller loses transport, do not infer owner death. Inspect tries owner nonblocking; if live return in_progress, otherwise reconcile under owner and metadata (never invoke runtime). A legacy task owns device across primary/selector/recovery/restart; legacy registry mutations for that family acquire same device owner, recheck generation, preserve old exclusion. Unrelated B progresses.

Claim state: reserved -> running -> terminal; running may be abandoned only after actual owner lock acquired. Reservation does not permit effect. Owner token set with running state before input. Persist per-step pending intent + epoch increment before possible input; effect may have happened after that point, so unknown on crash, never roll back epoch. Verified receipt after actual post observation. Crash before pending retains not_attempted for that step, not claim of no earlier step effects. Completed receipts immutable, duplicate projection read only. For new guarded click, successful dispatch completed/executed_unverified; raw coordinate legacy has no caller ID, advances epoch but no at-most-once promise across explicit repeated raw calls. Reconciliation never resumes. Old running JSON receipts under new owner rules inspect/reconcile only, no replay.

## K05. Execution context, proof and qualification
ResolvedDefinition = immutable portable or legacy identity + original workflow ID/source device + definition/source seal + required geometry + decoded, hash-verified template bytes + ordered state/step specs. Legacy resolver keeps source-device equality; portable resolver verifies original sealed source separately, never substitutes target serial into legacy binding. ExecutionContext = {kind:"legacy"|"trial"|"portable_run",definition_id,source_workflow_id,source_seal,device,profile,geometry,admission_id,binding_id nullable,qualification_id nullable}; context produced only by validated admission/trial, not arbitrary caller context. Legacy binding_id required only for legacy; trial qualification_id null; admitted portable_run pins qualification_id. Interpreter accepts owner context and ResolvedDefinition; state matching/unique target/epoch/freshness/postcondition verification shared; legacy guard remains in legacy wrapper. Proof verifier accepts expected context + actual run receipt and pinned dependency snapshot; checks kind, IDs, device/profile/geometry, every step order/status, complete final state and verified action_outcome, actual frame hashes, unique fresh target refs, target bbox/template match, reference epoch/chronology and action receipt source/device/coordinates. Legacy proof retains old exact output shape and no retroactive epoch requirement for old evidence. New proof requires epoch evidence. Source A enrollment uses separate legacy-source path, only first commit. New portable proof contains seal of complete run/context, frame/ref/template evidence; no alternate relaxed verifier.
Qualification slots are independent of family activation. Commit reads expected slot generation (absent=0), validates proof outside lock using pinned source/trial snapshot, then compares and increments generation in atomic metadata transaction. Revoke requires existing active slot, increments generation, retains qualification_id for history; absent -> NOT_FOUND; inactive -> QUALIFICATION_INACTIVE except exact duplicate mutation receipt. Commit after revoke/invalidation requires fresh trial completed after slot transition; active replacement requires new valid trial unless exact duplicate operation. Operation digest canonical request incl expected generation, proof identity/assertion or revoke reason; exact duplicate returns original receipt, never mutates, inspect gives current slot. Qualification ID excludes timestamps, includes portable_id, serial, exact profile/geometry, proof seal, semantic assertion. Family generation increments only on publish/activate/disable; qualification slot CAS independent even across families referencing same portable_id. Admission pins both generations + qualification_id atomically after validating source/proof snapshot. Invalidation: read active slot identity/generation before actual profile/geometry probe; on confirmed mismatch under device owner compare current slot and invalidate exact observed active slot in short transaction, increment slot generation, record observed/expected/reason/time; never invalidate newer replacement from old observation. Probe timeout/offline/malformed is not confirmed drift. New admission requires active slot; matching profile after invalidation does not reactivate. Runtime admitted before revoke may finish only while live guards pass; drift stops before next possible input, preserves actual last frame and uncertainty. Device serial reuse is logical identity limitation; operator can explicitly revoke before replacement. No physical identity inference. New revision requires independently valid slot, never copied. Preflight/trial does not enroll automatically.
Legacy compatibility: registry register/switch/route mutation resolves device under read snapshot, releases metadata, takes same device owner, rechecks identity/generation and proof before mutation; task holds that owner across entire recovery chain. Standalone legacy run takes same device owner before guard; offline inspect does not acquire device owner unless reconciling unfinished request. Existing family behavior for activation, inactive runs, recovery eligibility, duplicate and receipts preserved. No automatic portable recovery.

## K06. Batch and crash state machine
Parent transaction validates strict online discovery snapshot, unique explicit serial list and active qualified slots, expected family generation, proof/source revisions, reserves all ptask_/prun_ IDs with pinned context, records open phase, before dispatch. Discovery I/O and proof validation outside metadata; recheck revisions and claim conflicts at commit; target disconnect after discovery is child live admission failure. Same request duplicate lookup FIRST, even if registry changed/offline, never re-dispatch. Parent owner acquired before admission and held while dispatching/joining. Child owner independently acquired, claim reserved->running under metadata only if parent admission open; child cannot independently claim reserved ID via standalone execute. Child already running may complete after parent loss; no new claim after phase closed. Parent never waits for child/device under metadata; no child reacquires parent owner. Max 4 worker slots per batch, requested max_concurrency default 2; no global concurrency guarantee across separate batches beyond per-device exclusion. Child task and run share owner and device lock; both receipts persisted before effect. Recheck live guards on device owner, busy/rejected/needs_agent recorded child terminal; no child retry or cross-device recovery.
If parent owner unavailable, inspect returns current receipt in_progress, no mutation of live parent. If owner acquired and nonterminal, atomically close admission, mark still-reserved children not_attempted (no effect), then inspect running child owner without blocking: if held, leave in_progress and parent phase reconciling; if acquired, reconcile durable pending/action/verified evidence and terminal status only, never run. Reconcile child run then task and parent counts. Do not mark surviving child interrupted merely because parent ended. Later inspect repeats only reconciliation; phase closed/reconciling cannot launch anything. Crash after terminal child but before parent update uses authoritative child receipt. Terminal batch immutable; inspect never changes completed child. Parent status table:
| condition (in precedence order) | status | phase |
|---|---|---|
| any child reserved/running with live parent, or live surviving child | in_progress | open/reconciling |
| all children completed | completed | terminal |
| abandoned admission with any not_attempted/interrupted child | interrupted | terminal |
| all terminal, at least one completed and at least one non-completed (no abandonment above) | partial | terminal |
| all terminal, none completed, no abandonment above | needs_agent | terminal |
Reserved child before parent close is counted in_progress; not_attempted after close. Child action_outcome remains factual, pending means unknown, previously verified steps not erased; no implicit restart. A child busy or rejected before input is not_attempted outcome, not successful. Batch inspection returns per-device IDs/status/reasons and aggregate counts; no image fan-out. Full frame and child evidence through inspection. Transport timeout is not owner death or task failure.
