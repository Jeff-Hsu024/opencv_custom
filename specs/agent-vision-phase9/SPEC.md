## Problem Statement
A device can be selected by ADB serial today, but a learned workflow is bound to its source serial. Repeating a task on another compatible Android instance requires redundant learning. A store-wide operation lock prevents independent devices from progressing concurrently. Merely removing the source-device check or replacing the lock would violate current provenance and shared JSON-index integrity.

## Solution
Publish one proven learned workflow as an immutable portable revision; establish an explicit, independently evidenced qualification for each compatible device; execute single or bounded batch requests with fresh device-local guards, durable idempotent receipts and per-device exclusion. Preserve the v1 API, bundle and evidence. Extend the application layer, not Core or Queqiao Adapter.

## Implementation Decisions (normative)
### R01 — Discovery and scope (UC01,08,09)
Keep existing vision_devices response and CLI devices; ensure actual adb state token equals device, not substring; reject aliases adb/desktop for portable operations; explicit exact serial, no implicit first device, no connect/launch; unavailable serial => DEVICE_UNAVAILABLE; invalid serial => INVALID_DEVICE. Existing desktop operations remain supported outside portable APIs. Discovery itself is read-only and can be empty. Resolve serial through trusted ADB configuration, not shell string interpolation. One host, one ADB server, one shared store. Serial aliases to same physical device are out of scope, documented; no claim of isolation from external controllers.

### R02 — Proven portable definition (UC02,03,14)
Legacy Workflow v1 stays byte-identical and source-device bound. New portable definition schema 1 is a separate content-addressed object portable_<64 lowercase hex>, digest of canonical schema, source workflow ID/definition seal, verified source run/proof seal, immutable exact required profile (package, version_code, rotation, locale, ui_mode), geometry (width, height, rotation), existing ordered state/target/template contracts and goal. No target device in portable execution identity; source serial remains provenance in the sealed source, never default target. Verify existing full source run proof with the existing Lifecycle proof rules and builder offline validation on source device before publication. Source proof and protected frames/templates stay retained. Repeated publication returns same ID; content changes produce new ID. Reject missing/tampered/partial proof before creating portable object. Reuse existing template bytes and matcher, not copy a mutable workflow per target. Revalidate immutable source seal before use; task-local validation cache scoped to immutable object and exact revision only.

### R03 — Read-only preflight (UC04,09)
New portable preflight requires portable_id and explicit device. Read actual profile on that serial; exact match to required profile, exact geometry, unique initial state and first target. Persist fresh target-device observation and structured receipt preflight_<64 hex> keyed to immutable revision/device/profile/geometry plus observation; no action. Preflight is not enrollment or a reusable action ref. Distinguish PROFILE_MISMATCH, GEOMETRY_MISMATCH, INITIAL_STATE_MISMATCH, TARGET_NOT_FOUND, TARGET_AMBIGUOUS, DEVICE_UNAVAILABLE, evidence error. If capture fails before valid frame, null observed frame. Profile/geometry/state checked again at trial admission and every runtime step, never rely solely on historical preflight.

### R04 — Trial and qualification (UC05,09,11)
Explicit portable trial request with preflight_id and caller prun_<32 hex>; task owner selects authorized device via preflight (request also includes device, must match). Trial is a real bounded run, same verified deterministic interpreter and fresh target-device refs as legacy; no automatic retry or recovery. Pin portable_id, device, exact profile/geometry. Before every input persist intent; every postcondition check uses actual target-device frame. Trial completion alone does not enroll device: explicit qualify_commit with completed matching trial and semantic PASS assertion (nonempty observation, reviewer identity label; no identity/authentication claim). Verify all step guards, receipts, hashes, chronology and unique fresh refs through reused proof verifier parameterized by target device. No source-device frames or refs as target proof. A can be enrolled through explicit commit of the original completed source proof, if exact revision/profile/geometry and all proof checks match; B cannot. Qualification qlf_<64 hex> is content-addressed by portable_id/device/profile/geometry/proof seal and semantic assertion; registry stores current qualification per pair, previous records immutable. Revoke or replace via CAS. On drift, reject future admissions; do not silently transfer a qualification. Same profile alone is insufficient. Failed, interrupted or non-PASS trials cannot enroll. Inspection includes explicit reason and actual last frame.

### R05 — Portable family, revision and admission (UC06,12,14)
Separate additive portable family namespace, no change to existing workflow_families primary key or proof rules. Family identifier slug; revision number monotonically increasing, immutable mapping to portable_id, explicit active revision, family generation CAS for publish/activate/disable; qualification revoke uses independent slot CAS (R13). Device enrollment tied to portable_id and serial, not a mutable family default. Activation never copies earlier qualifications to new revision. New task admission pins active revision, generation and exact qualification ID; stale expected generation, inactive family, missing/revoked qualification rejected before input. Existing admitted executions may finish their pinned revision; changes affect future admissions, not in-flight cancellation. Explicit list/inspect includes active revision and device qualifications, pagination/summary and stable IDs. No auto promotion or device selection.

### R06 — Single portable execution (UC06,09,11)
New portable execute requires family_id, expected_generation, explicit device and ptask_<32 hex>. Persist normalized request and pinned revision/proof before first effect. Shared interpreter uses validated portable definition and target-bound qualification, not legacy source-bound binding; legacy _definition guard remains. Fresh capture, exact profile/geometry, unique state/target, target ref age and device consistency checked at each step; same current deterministic click semantics. Reuse existing runtime receipts/failure evidence contracts; record source provenance separately. Return completed/needs_agent/interrupted/busy/rejected with action_outcome, completed_steps, last observed/confirmed state, device, actual frame, reason, run ID. No unknown effect replay, automatic recovery, implicit migration or batch eligibility from preflight only. Same ID/request returns stored result or in-progress state, no repeat; changed payload => REQUEST_ID_CONFLICT. IDs scoped across legacy and portable namespaces or explicitly disjoint kind prefixes with no collision; validate cross-kind IDs before action. All task/run/transition claims atomic across processes.

### R07 — Concurrency and storage integrity (UC07,08,11,13,14)
Do not simply remove workspace_lock. Expand–migrate–contract: add a store-wide short metadata transaction/lock and OS-backed cross-process per-device execution lock keyed by canonical store + explicit serial (hash, no path injection); locks released on process death. All cooperating device I/O (including legacy bare input, recorded transition, wait, runtime, recovery and orchestrator) uses same device exclusion; same device busy within bounded admission timeout (portable <=2s; legacy existing 120s wait), no input on busy. Hold device lock through precondition/effect/postcondition transaction; never wait for device while holding metadata lock; internal already-locked calls do not reacquire. Multiple-device batch must not hold one device while waiting for another. Keep global metadata lock for shared ID claims, frame index read-modify-write, retention, pinning/cleanup, recorder writes and registry generation changes; no capture/poll/sleep or full runtime while holding it. Atomic replace alone is insufficient. Frame index updates protected as whole transactions, readers pin active evidence/refs or use consistent lock during read; retention never removes protected or active-use frames. Coordinate frame file publication/index update and orphan cleanup on crash; preserve current protected evidence semantics and existing size/TTL behavior. Registry CAS and task admission linearize; SQLite constraints remain. Read-only offline operations validate consistent sealed evidence; no global serialization of independent device waits. Lock order device -> metadata; batch owner -> metadata or child device (never metadata -> device); per-request owner token/OS lock distinguishes running from abandoned. One shared store and cooperating upgraded processes only; deployment requires quiescent old 0.2.0 writers. External ADB/desktop or separate stores are not covered by this lock contract. No new daemon.

### R08 — Bounded batch (UC07,10,11)
Synchronous portable batch API: batch_<32 hex>, family_id, expected_generation, explicit ordered devices array 1..16 unique serials, max_concurrency integer 1..4 default 2. No discovery-as-broadcast. Normalize exact request; reject duplicate/unknown/unqualified/stale generation/invalid size before any child input or dispatch. Pin all qualifications and revision in a durable parent admission transaction; deterministic child task/run IDs derived from batch ID + serial + role; collision check before execution. Child tasks use same single-execution contract and per-device lock. At most max_concurrency live child executions; independent devices overlap even through shared store. A single stdio call can run bounded internal workers; no assumption that concurrent calls to a single stdio server execute simultaneously. Busy or live drift after admission yields child result, others continue. Parent reports per-device outcomes and counts, completed if all completed, partial if some completed and others did not, needs_agent if none completed with failure, interrupted when parent abandoned with incomplete children. No fail-fast cancellation, automatic retries, rescheduling or recovery across devices. Transport loss is not evidence of execution failure. Inspect parent and child IDs; reconcile live owners read-only/in-progress; after acquiring abandoned owner lock reconcile completed child receipts, mark unstarted children not_attempted, pending unknown; never resume automatically. Bound summary and pagination; full child details by ID, no image fan-out in batch response.

### R09 — Agent contract, compatibility and migration (UC01–14)
Additive MCP names and CLI request-file interface are defined in CONTRACT.md and CONTRACT_SCHEMAS.json. Exact schema and error contracts are in CONTRACT.md; C00 freezes executable fixtures before implementation; existing 61 tool names/default responses unchanged. All new device-effect APIs require explicit serial (batch explicit list); use opaque IDs, bounded limits, metadata-only or actual ImageContent on single observation paths. Gateway typed image forwarding already supported by deployed adapter 0.1.2; no adapter changes. CLI and MCP share service and store. New tables/files additive, existing v1 IDs, source frames, run receipts, hashes, evidence paths unchanged; no in-place rewrite of v1 definitions. Migration tests using copied 0.2.0 store. Back up and quiesce before eventual release; no live migration or package deployment in this phase's planning.

### R10 - Scoped asset revision and reference lifetime (UC15, UC13; F01)
Add immutable asset revision ar_<sha256> with device, nullable session, label, source frame ID, canonical metadata and PNG digest. New registration and find/transition resolve explicit revision (or device/session-scoped alias), not global mutable name. Portable workflow matches sealed template bytes, never a live named alias. Store content before publishing committed pointer; readers resolve one revision and pin its source/image until finished. Metadata/pointer publication, recorded digest and ref creation cannot see mixed revisions. Legacy named API retains original shape and last-committed global alias; same-name cross-device legacy use still fails scope check in recorded paths; serialize its publication/lookup, never rewrite historical evidence. Existing names read as legacy, migrate lazily only when validated; interrupted publication must not expose torn pairs. Same explicit ID with different content is a conflict, not overwrite.

### R11 - Guarded action epoch (UC16, UC08; F02)
Durable monotonic epoch per exact serial in shared store. Capture full frame with epoch under device owner; derived frames and new scoped refs inherit it. New guarded action acquires owner, validates scope/geometry/freshness and exact current epoch, then atomically increments epoch and persists intent before any possible input. Any cooperating input including legacy raw/coordinate/text/key/swipe advances epoch even if outcome unknown. Pure observation does not advance. Old/unversioned refs cannot enter new guarded API; legacy unversioned ref/coordinate behavior and response shapes remain unchanged (explicitly not epoch-safe). Existing legacy ref calls on newly stamped refs reject stale epoch. No external UI change detection guarantee; existing fresh profile/state/target checks still required. Pending action crash conservatively invalidates prior references; no rollback of epoch.

### R12 - Shared interpreter and proof seam (UC03, UC05, UC06; F03)
Extract immutable definition resolver (legacy source-device guard retained in legacy entrypoint), target-bound ExecutionContext and proof verifier. Resolver loads verified source definition/templates and immutable evidence seal, does not probe or execute; context carries mode, target serial, required profile/geometry, sealed definition identity and pinned admission identity. Interpreter is shared, receives explicit context and owner token; no registry lookup or source-device substitution inside portable execution. Legacy wrapper retains lifecycle guard, legacy binding, receipt schema and original proof output. New portable trial/execute emit kind-specific target receipts and use same per-step state/target/chronology verifier. Verifier accepts only expected kind/identity/context and complete proof; no mutable admission or caller-supplied unverified profile. Source proof can enroll A only via distinct legacy-source proof path. Tampered kind, binding, source seal, substituted source frame/ref or incomplete proof rejected.

### R13 - Qualification slot lifecycle (UC17, UC12; F04)
QualificationSlot key (portable_id, serial), independent generation starting 0 for absent slot; active pointer plus immutable qualification record history. Commit/revoke require expected_slot_generation; commit validates completed matching trial and explicit semantic PASS; CAS increments by one. Same exact commit retry with same proof/assertion and original generation returns original immutable operation receipt, never reactivates a revoked/invalidated slot. New commit after invalidation requires a new completed trial after invalidation (source A may use source proof only for first enrollment). Confirmed profile/geometry mismatch invalidates matching active slot by CAS before response, increments generation, retains proof and reason; do not invalidate newer replacement based on old observation. Profile returns to original does not resurrect. Transport unavailable or unknown probe error alone is not drift. Serial denotes logical device identity, no physical attestation; explicit revoke/requalify when known replacement uses same serial. Admission snapshots family generation, slot generation, qualification ID in one metadata transaction. Family revision activation never copies enrollments. Revocation affects future admission, pinned admitted tasks still check actual live profile/geometry at each step and stop on drift. No family generation mutation for slot operations.

### R14 - Atomic claims and reconciliation (UC18, UC11, UC10; F05)
One additive SQLite coordinator ledger authoritative for admission, reservation, request identity, owner claims, terminal status. Atomic transaction reserves parent and every child task/run ID and pins exact qualification/version before dispatch; standalone request cannot claim reserved child. Reserve no effects on invalid admission. Normalized same ID lookup precedes current-generation/device checks; conflicts fail before action; duplicate only inspect. Separate cross-process owner locks for parent and independent children; child claims only while admission open and owner acquired, never replay. Parent loss closes admission before reconciling unclaimed children. A live child may finish, cannot be marked interrupted until owner lock acquired; no rescheduling. Persist pending before effect, preserve unknown after abandoned pending. SQLite journal is authoritative for new lifecycle; existing JSON receipts remain legacy and new projections cannot create a second source of truth. See contract truth table and crash ordering.

### R15 - Evidence snapshot and publication (UC19, UC13; F06)
All cooperating evidence mutations (including session status, append annotation/checkpoint/dispute, frame metadata/protection, asset revision, refs, retained template/definition publication) participate in metadata transaction and evidence revision tracking. Under short metadata transaction capture immutable pinned dependency snapshot and seal; validate outside lock; at commit recheck dependency revision/complete seal and publish atomically or EVIDENCE_CHANGED. Pin files for entire read/validation; never cache mutable proof without current dependency seal. Existing source sessions/annotations remain appendable; later disputes invalidate subsequent admission/publication, not rewrite historical proof. Already admitted portable context is immutable snapshot; runtime live guards remain. Legacy proof validation uses same consistency seam, no weaker proof.

### R16 - Compatibility activation and contract freeze (UC20, UC21; F07)
Legacy managed family mutations (register/activate/disable/route changes) resolve family device then acquire same device owner before metadata CAS; re-read generation under lock. Legacy orchestrator holds owner across primary, selector, recovery and restart, preserving old same-device activation exclusion; unrelated devices can progress. Legacy bound wait semantics (up to existing 120s) and old shapes preserved; new portable owner contention <=2s. Strict device discovery new API distinguishes successful empty from command failure; old vision_devices unchanged shape, exact ADB state token fix permitted in Core parser only, no wider refactor. Existing 61 names remain; new contract schema and fixture tests precede implementation. Compatibility gate remains until C11 audit all paths; never mix old binary writers with new Store. See CONTRACT.md for exact namespace and API.
