# Phase 9 — Portable workflow and multi-device execution SPEC
Status: PROPOSED / planning only. Parent release: agent-vision-v0.2.0 (bfbec17fe55b25a2ea7ddbd9051cc3937ccd3efb).
Source: USE_CASES.md, UC01–UC14; SHA-256 22eae285bacffa3609aabb68b6aced3b38a45ff4c8f67c0cc341a559b27a3e7c (UTF-8, LF-normalized).
Decisions are proposed for review before implementation. Do not deploy, run a real trial, or dispatch tickets solely from this document.

## Problem Statement
A device can be selected by ADB serial today, but a learned workflow is bound to its source serial. Repeating a task on another compatible Android instance requires redundant learning. A store-wide operation lock prevents independent devices from progressing concurrently. Merely removing the source-device check or replacing the lock would violate current provenance and shared JSON-index integrity.

## Solution
Publish one proven learned workflow as an immutable portable revision; establish an explicit, independently evidenced qualification for each compatible device; execute single or bounded batch requests with fresh device-local guards, durable idempotent receipts and per-device exclusion. Preserve the v1 API, bundle and evidence. Extend the application layer, not Core or Queqiao Adapter.

8. As an auditor I want semantic acceptance tied to a complete actual trial, not inferred from a single image (UC05).
9. As an agent I want to execute an active portable revision by serial without learning again (UC06).
10. As an agent I want original-ID inspection after a lost response and never repeat a prior click (UC06, UC11).
11. As an operator I want a bounded batch of explicit devices to execute concurrently (UC07).
12. As an operator I want device-local exclusivity across cooperating CLI/MCP processes (UC08).
13. As an agent I want mismatched profile/state/geometry to stop action before input (UC09).
14. As an auditor I want post-action uncertainty to retain the actual latest frame (UC09–11).

## Implementation Decisions (normative)
### R01 — Discovery and scope (UC01,08,09)
Keep existing vision_devices response and CLI devices; ensure actual adb state token equals device, not substring; reject aliases adb/desktop for portable operations; explicit exact serial, no implicit first device, no connect/launch; unavailable serial => DEVICE_UNAVAILABLE; invalid serial => INVALID_DEVICE. Existing desktop operations remain supported outside portable APIs. Discovery itself is read-only and can be empty. Resolve serial through trusted ADB configuration, not shell string interpolation. One host, one ADB server, one shared store. Serial aliases to same physical device are out of scope, documented; no claim of isolation from external controllers.

### R02 — Proven portable definition (UC02,03,14)
Legacy Workflow v1 stays byte-identical and source-device bound. New portable definition schema 1 is a separate content-addressed object portable_<64 lowercase hex>, digest of canonical schema, source workflow ID/definition seal, verified source run/proof seal, immutable exact required profile (package, version_code, rotation, locale, ui_mode), geometry (width, height, rotation), existing ordered state/target/template contracts and goal. No target device in portable execution identity; source serial remains provenance in the sealed source, never default target. Verify existing full source run proof with the existing Lifecycle proof rules and builder offline validation on source device before publication. Source proof and protected frames/templates stay retained. Repeated publication returns same ID; content changes produce new ID. Reject missing/tampered/partial proof before creating portable object. Reuse existing template bytes and matcher, not copy a mutable workflow per target. Revalidate immutable source seal before use; task-local validation cache scoped to immutable object and exact revision only.

### R03 — Read-only preflight (UC04,09)
New portable preflight requires portable_id and explicit device. Read actual profile on that serial; exact match to required profile, exact geometry, unique initial state and first target. Persist fresh target-device observation and structured receipt preflight_<64 hex> keyed to immutable revision/device/profile/geometry plus observation; no action. Preflight is not enrollment or a reusable action ref. Distinguish PROFILE_MISMATCH, GEOMETRY_MISMATCH, INITIAL_STATE_MISMATCH, TARGET_NOT_FOUND, TARGET_AMBIGUOUS, DEVICE_UNAVAILABLE, evidence error. If capture fails before valid frame, null observed frame. Profile/geometry/state checked again at trial admission and every runtime step, never rely solely on historical preflight.

### R04 — Trial and qualification (UC05,09,11)
Explicit portable trial request with preflight_id and caller run_<32 hex>; task owner selects authorized device via preflight (request also includes device, must match). Trial is a real bounded run, same verified deterministic interpreter and fresh target-device refs as legacy; no automatic retry or recovery. Pin portable_id, device, exact profile/geometry. Before every input persist intent; every postcondition check uses actual target-device frame. Trial completion alone does not enroll device: explicit qualify_commit with completed matching trial and semantic PASS assertion (nonempty observation, reviewer identity label; no identity/authentication claim). Verify all step guards, receipts, hashes, chronology and unique fresh refs through reused proof verifier parameterized by target device. No source-device frames or refs as target proof. A can be enrolled through explicit commit of the original completed source proof, if exact revision/profile/geometry and all proof checks match; B cannot. Qualification qlf_<64 hex> is content-addressed by portable_id/device/profile/geometry/proof seal and semantic assertion; registry stores current qualification per pair, previous records immutable. Revoke or replace via CAS. On drift, reject future admissions; do not silently transfer a qualification. Same profile alone is insufficient. Failed, interrupted or non-PASS trials cannot enroll. Inspection includes explicit reason and actual last frame.

### R05 — Portable family, revision and admission (UC06,12,14)
Separate additive portable family namespace, no change to existing workflow_families primary key or proof rules. Family identifier slug; revision number monotonically increasing, immutable mapping to portable_id, explicit active revision, family generation CAS for publish/activate/revoke. Device enrollment tied to portable_id and serial, not a mutable family default. Activation never copies earlier qualifications to new revision. New task admission pins active revision, generation and exact qualification ID; stale expected generation, inactive family, missing/revoked qualification rejected before input. Existing admitted executions may finish their pinned revision; changes affect future admissions, not in-flight cancellation. Explicit list/inspect includes active revision and device qualifications, pagination/summary and stable IDs. No auto promotion or device selection.

### R06 — Single portable execution (UC06,09,11)
New portable execute requires family_id, expected_generation, explicit device and task_<32 hex>. Persist normalized request and pinned revision/proof before first effect. Shared interpreter uses validated portable definition and target-bound qualification, not legacy source-bound binding; legacy _definition guard remains. Fresh capture, exact profile/geometry, unique state/target, target ref age and device consistency checked at each step; same current deterministic click semantics. Reuse existing runtime receipts/failure evidence contracts; record source provenance separately. Return completed/needs_agent/interrupted/busy/rejected with action_outcome, completed_steps, last observed/confirmed state, device, actual frame, reason, run ID. No unknown effect replay, automatic recovery, implicit migration or batch eligibility from preflight only. Same ID/request returns stored result or in-progress state, no repeat; changed payload => REQUEST_ID_CONFLICT. IDs scoped across legacy and portable namespaces or explicitly disjoint kind prefixes with no collision; validate cross-kind IDs before action. All task/run/transition claims atomic across processes.

### R07 — Concurrency and storage integrity (UC07,08,11,13,14)
Do not simply remove workspace_lock. Expand–migrate–contract: add a store-wide short metadata transaction/lock and OS-backed cross-process per-device execution lock keyed by canonical store + explicit serial (hash, no path injection); locks released on process death. All cooperating device I/O (including legacy bare input, recorded transition, wait, runtime, recovery and orchestrator) uses same device exclusion; same device busy within bounded admission timeout (default nonblocking or <=2s documented), no input on busy. Hold device lock through precondition/effect/postcondition transaction; never wait for device while holding metadata lock; internal already-locked calls do not reacquire. Multiple-device batch must not hold one device while waiting for another. Keep global metadata lock for shared ID claims, frame index read-modify-write, retention, pinning/cleanup, recorder writes and registry generation changes; no capture/poll/sleep or full runtime while holding it. Atomic replace alone is insufficient. Frame index updates protected as whole transactions, readers pin active evidence/refs or use consistent lock during read; retention never removes protected or active-use frames. Coordinate frame file publication/index update and orphan cleanup on crash; preserve current protected evidence semantics and existing size/TTL behavior. Registry CAS and task admission linearize; SQLite constraints remain. Read-only offline operations validate consistent sealed evidence; no global serialization of independent device waits. Lock order device -> metadata; batch owner -> metadata or child device (never metadata -> device); per-request owner token/OS lock distinguishes running from abandoned. One shared store and cooperating upgraded processes only; deployment requires quiescent old 0.2.0 writers. External ADB/desktop or separate stores are not covered by this lock contract. No new daemon.

### R08 — Bounded batch (UC07,10,11)
Synchronous portable batch API: batch_<32 hex>, family_id, expected_generation, explicit ordered devices array 1..16 unique serials, max_concurrency integer 1..4 default 2. No discovery-as-broadcast. Normalize exact request; reject duplicate/unknown/unqualified/stale generation/invalid size before any child input or dispatch. Pin all qualifications and revision in a durable parent admission transaction; deterministic child task/run IDs derived from batch ID + serial + role; collision check before execution. Child tasks use same single-execution contract and per-device lock. At most max_concurrency live child executions; independent devices overlap even through shared store. A single stdio call can run bounded internal workers; no assumption that concurrent calls to a single stdio server execute simultaneously. Busy or live drift after admission yields child result, others continue. Parent reports per-device outcomes and counts, completed if all completed, partial if some completed and others did not, needs_agent if none completed with failure, interrupted when parent abandoned with incomplete children. No fail-fast cancellation, automatic retries, rescheduling or recovery across devices. Transport loss is not evidence of execution failure. Inspect parent and child IDs; reconcile live owners read-only/in-progress; after acquiring abandoned owner lock reconcile completed child receipts, mark unstarted children not_attempted, pending unknown; never resume automatically. Bound summary and pagination; full child details by ID, no image fan-out in batch response.

### R09 — Agent contract, compatibility and migration (UC01–14)
Proposed additive MCP names: vision_portable_publish, vision_portable_inspect/list, vision_portable_preflight, vision_portable_trial, vision_portable_qualify_commit, vision_portable_qualification_list/revoke, vision_portable_family_publish/activate/inspect/list, vision_portable_execute, vision_portable_batch_execute, vision_portable_task_inspect/list, vision_portable_batch_inspect/list. CLI groups mirror operations (vision portable ...). Final exact schemas/error envelopes frozen before implementation; existing 61 tool names/default responses unchanged. All new device-effect APIs require explicit serial (batch explicit list); use opaque IDs, bounded limits, metadata-only or actual ImageContent on single observation paths. Gateway typed image forwarding already supported by deployed adapter 0.1.2; no adapter changes. CLI and MCP share service and store. New tables/files additive, existing v1 IDs, source frames, run receipts, hashes, evidence paths unchanged; no in-place rewrite of v1 definitions. Migration tests using copied 0.2.0 store. Back up and quiesce before eventual release; no live migration or package deployment in this phase's planning.

## Testing Decisions
- Highest seams: CLI/MCP public invocation against a temporary shared store with injected device platforms and profile probe; real subprocesses for cross-process lock and index races; deterministic barriers/events for overlap, not timing-only assertions. Reuse existing ObservationService/ActionService fake seam, recorder/runtime/lifecycle/orchestrator and failure-evidence tests. Do not mock proof checks, storage integrity or lock ownership to make a test pass.
- A01 (R01/UC01): two online serials, offline/unauthorized excluded, explicit target and no cross-device I/O. A02 (R02/UC02–03): valid publish; duplicate same ID; tampered source rejection and unchanged legacy hashes.
- A03 (R03/UC04): exact B preflight, zero input, mismatch matrix and last evidence. A04 (R04/UC05): trial all steps, semantic PASS qualification, reject wrong device, partial/failed/unknown proof, requal after drift.
- A05 (R05–06/UC06,12): same revision on A/B with new refs, task-ID conflict/idempotency, generation pin and revocation. A06 (R07/UC07–08,13): two real process workers overlap via barrier; same device contention, race between raw CLI and recorded MCP, stress concurrent frame save/protect/TTL and inspect; no lost rows, invalid refs, orphan protected files; SQLite integrity; no deadlock.
- A07 (R08/UC07,10): explicit batch prevalidation, max concurrency, child ID determinism, per-device failures, no hidden clicks. A08 (R06–08/UC11): kill process between pending click and receipt, parent loss, duplicate during live owner, transport timeout inspect, no replay.
- A09 (R09/UC13–14): 308 prior distinct cases + new cases, CLI/MCP parity, legacy store copied hash audit, schema compatibility, no frozen mutation. Existing test count is prior qualification evidence, not newly run here.
- A10 (UC02–14): independent fresh agent starts from source learning on A and qualifies B from same portable definition, zero new B exploration, two repeated runs each, actual batch overlap, final same reversible screen, raw evidence/SQLite audit. Synthetic fixture PASS cannot substitute for two-device real E2E. Only one serial was discovered in prior release; actual second device is not yet established. No live actions in this planning task. If unavailable, report live gate NOT_ATTEMPTED/BLOCKED rather than claiming acceptance. Live test only authorized isolated stores/devices, no account/currency/settings changes.

## Out of Scope
Cross-host scheduling, automatic device enrollment or recovery, adaptation across geometry/app version/locale, new action types, account automation, asynchronous job daemon, external controller arbitration, distributed Store, new Core/OpenCV algorithm, Queqiao transport rewrite, production deployment, changing frozen 0.2.0 source or tags. Portable automatic recovery is deferred; legacy recovery unchanged.
