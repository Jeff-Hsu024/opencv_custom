# Agent Recovery & Replanning v1
Application-layer bridge from a failed/interrupted Runtime run to a new recorded exploration, and evidence-bound child workflow. Runtime remains deterministic; no embedded LLM, autonomous retry, or workflow mutation. One case per failed run, one dedicated Recorder session created atomically in recorder SQLite. Case seals original terminal run hash and parent binding/profile; completed runs cannot open cases. Running receipt under acquired workspace lock is interrupted (no active writer); no replay. Handoff returns reason, last actual frame, current step, verified prefix, original action outcome, goal, known states and remaining path, bounded. Historical state is not current state.
Agent must observe fresh full snapshot in linked session before any recovery action, annotate explicit PASS on observed state and reconcile original action outcome (not_attempted, effect_observed, effect_not_observed, unknown). Reconciliation is agent statement, never changes original receipt. Unknown may yield safe recovery route, never authorize retry of uncertain original action. No automatic suffix execution. Plan uses existing Builder evidence chain; first pre-snapshot is anchor or a later fresh frame with matching parent and child state guards; no intervening actions; every action accounted for; no exclusions in recovery session. Parent and child source device match. Route must finish at explicitly named parent state uniquely recognized on actual final frame; anchor may be unknown to parent but cannot be ambiguous. Full replacement option requires original initial and final state guards on actual endpoints; no automatic splice of verified prefix. Parent profile independently checked during later child live qualification, not inferred from old capture. Proposal immutable, content-addressed, preserves original parent ID, case/run/session/anchor/annotation hashes and reconciliation. Same input idempotent. Offline validation only; live qualification requires subsequent completed child Runtime run with same device/profile and proposal-time ordering, unique state endpoint and bundle/source hashes revalidated. Qualification receipt is immutable and does not promote/default/modify any workflow. No automatic actions from recovery service. CLI/MCP open/inspect/propose/verify/list. Existing Recorder, Builder and Runtime APIs preserved; application-level locking, atomic DB case/session creation. Limit one case/session per run, at most 20 proposals returned with pagination via separate list; v1 does not resolve conflicting concurrent external device controllers.
