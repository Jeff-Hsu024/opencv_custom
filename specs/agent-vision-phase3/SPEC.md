# Workflow Builder v1
Application-layer offline compiler, not a runtime. Source is one stopped Recorder session. No device calls or modifications to Recorder data. Candidate discovery lists all action events (including failed/pending/unsupported), paginated. LLM selects explicit semantic state markers and action/find/wait/post-observation/annotation event IDs. No automatic semantic inference.
V1 supports reference-based click transitions only; swipe/type/key/frame-point click are visible but unsupported, never silently compiled. A plan explicitly accounts for every action event in the session (selected or excluded with reason); failed or pending actions within the selected path cannot be hidden, and omitted successful actions inside a transition or between transitions invalidate it. Offline compile requires sequential connected states, fresh full-frame source snapshots, unique matching scoped reference, retained asset SHA-256, actual click receipt, actual bounded changed wait, subsequent full snapshot, explicit PASS annotation linked to that snapshot. No other action between find, click, wait and verification. Raw coordinates and ephemeral refs are provenance only.
State markers are explicit ROI crops from actual full snapshots (agent-selected); each state has positive and negative fixture snapshots drawn from the selected path. Verify every marker against all path pre/wait/post frames, positives uniquely match and negatives do not match. Use existing OpenCvService matching; target uniqueness and original bbox checked on pre-action frame. Templates are content-addressed, no base64 in definitions. Device/resolution and color mode/threshold are explicit; unknown or wrong state fails closed. Workflow step is state guard -> fresh unique target match -> one click -> bounded post-state guard; no retry. A changed wait is evidence, not semantic proof. The builder only produces declarative data, never executes a device action.
Immutable versioned bundle under store/workflows/wf_<sha256>: definition.json (schema version, source session, ordered steps, states, assets, evidence IDs, offline checks, event/frame/ref/annotation hashes, explicit limitations), plan.json, templates/<sha256>.png. Atomic directory publish, no overwrite. Validate rechecks source evidence, bundle digest and template integrity. List/inspect/validate via CLI and MCP. Bundle references relative template paths only; no absolute paths in runtime contract. Build failure does not publish a workflow. Offline PASS is not runtime qualification. No live replay, recovery learning, arbitrary scripts, account changes or core modifications.

## Runtime handoff contract
The compiler produces a content-addressed immutable ID from canonical plan and definition; identical inputs are idempotent. Evidence hashes cover selected events, annotations, scoped references and pre/wait/post PNGs. Actual wait output must match the destination guard too; source geometry and timestamps must be consistent. The future runtime must bind application identity (not recorded in Phase 2), check current geometry/rotation/theme/locale, capture fresh frames, classify exactly one expected state, resolve a unique current target, perform one click, and check the destination guard within the declared timeout. Unknown/ambiguous states stop and return control to the agent. This is a declarative contract, not executable code. Offline checks are derived from a single exploration, not independent held-out live samples. The original Recorder session remains authoritative.
Limits: at most 1000 source events and annotations, 20 states and steps, 64 KiB plan; candidate page 1..50. The full immutable definition may be larger than a single page; inspect only when needed. Workflows are stored alongside, not inside, Recorder DB. The bundle is a self-contained template/definition package; source-session revalidation requires its original Recorder store.
